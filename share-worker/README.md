# DropSpace encrypted Internet Share worker

This Cloudflare Worker is the reference backend for the v0.3.0-preview.7 encrypted Internet Share path. It stores only opaque ciphertext in R2. The AES-256-GCM master key is generated by the Windows client and remains in the URL fragment (`#k=...`), so it is never sent in an HTTP request.

The worker is intentionally not deployed by the repository workflow. A maintainer must create an R2 bucket, configure `wrangler.toml`, set a high-entropy `UPLOAD_TOKEN_SECRET`, review the Cloudflare account/network policy, and deploy it explicitly. Until that is done, the desktop app must keep Internet Share disabled; Nearby Share remains the local-LAN option.

## Local setup

```powershell
Copy-Item wrangler.toml.example wrangler.toml
wrangler r2 bucket create dropspace-share-preview
wrangler secret put UPLOAD_TOKEN_SECRET
wrangler deploy
```

Set the resulting Worker URL as the desktop backend URL. The backend endpoint must be HTTPS. Keep R2 lifecycle expiration enabled as a second cleanup layer; the Worker also checks the encrypted share expiry on every request.

The browser receiver uses WebCrypto, validates the manifest and each chunk hash, supports multiple files, and never renders a directory listing. The desktop/Worker wire contract is `12-byte manifest nonce | manifest ciphertext | 16-byte tag` and `chunk ciphertext | 16-byte tag`; object names and upload metadata are bounded and authenticated. Logs must not include `#k=` fragments or request bodies.


The Worker requires the `SHARE_COORDINATOR` Durable Object binding shown in `wrangler.toml.example`. It is the authoritative concurrency-safe ledger for the token's aggregate item and plaintext-byte limits; requests fail closed when the binding is absent. The revoke path marks the coordinator first and paginates R2 deletion, so a large share cannot leave undeleted objects after the first listing page.

## Receiver download memory boundary

The receiver prefers the browser File System Access API (showSaveFilePicker) when available. It decrypts and hashes one chunk at a time, writes each plaintext chunk directly to the selected file, and aborts the destination if integrity verification fails. Browsers without that API keep a bounded in-memory fallback of 256 MiB; larger files fail with an explicit message instead of attempting an unbounded Blob allocation.

# Native worker provenance and qualification

`PlainLyrics/main.mm` and `gpu-policy.h` originate from Windows baseline `1cd4620dd58a67b0963b73487743137813b8864a`, `tools/plain-lyrics-helper`. Frozen model bytes, prompts, sampler settings, protocol1/selectionProtocol2, bounded frames and prefix caching remain in the native source. Platform changes replace Vulkan adapter admission with public Metal capability/working-set and public Mach VM free/inactive-page estimates. Modes are `cpu` and `metal`; failure codes65/66 require confirmed process exit before host CPU fallback.

Pinned llama.cpp source: `7fe450e19305b828c199d602c23a8337aaa1f03b` from https://github.com/ggml-org/llama.cpp . The1.8B model was downloaded through the native shared downloader, fully hashed and leased. Separate real CPU/Metal short-sentence probes passed. The worker hashes the exact regular file through a retained no-follow descriptor and loads `/dev/fd/N`; replacing the original path cannot substitute another model.7B has not been downloaded/evaluated. Resident host ownership and full-song native CPU/Metal UI now passed focused checks; see CORE-CONTRACTS and EXECUTION for remaining acceptance.

The Metal admission reserve is at least1GiB or20% of recommended working set, plus the unchanged per-model GPU allowance; estimated reclaimable host bytes must cover model+host allowance. This is a documented native replacement for discrete VRAM/vendor probing, not identical Windows memory telemetry. Memory-pressure transition and CPU fallback tests remain release gates.

Build correction: the SDK marks `os_proc_available_memory` unavailable on macOS. It was removed; no unavailable or private API is linked. Mach free+inactive pages are explicitly labeled an estimate. The controlled1.8B probes enforce a3GiB process RSS ceiling and1GiB startup reserve and confirm exit. The production host now uses Dispatch memory-pressure events and proc_pidinfo RSS checks during I/O and idle; cancellation confirms child exit. Actual pressure-transition and full failure tests remain open. The baseline7B process ceiling is12GiB, requiring a separate startup reserve; its probe has not run.

`FastText/main.cpp` builds engine commit `1142dc4c4ecbc19cc16eee5cdd28472e689267e6` from https://github.com/facebookresearch/fastText. It maps/hashes the unchanged131266198-byte model, reads upstream's magic/version header, then loads the same mapping and emits top-two predictions. The first real load exposed the previously missing header read; its correction is covered by actual en/zh predictions. The Swift host owns bounded nonblocking pipes, validated readiness/request identity, one serialized CPU model, original/provider role-separated128-entry/10-minute LRU and confirmed exit on cancellation. Whole-track sample/admission rules now feed the source coordinator. Full-document samples up to the parser budget are retained, with a16MiB wire bound instead of silently truncating at32KiB. Actual model/long-input/cache-role/cancellation tests and the bundled app clear/reload/quit flow passed. This is language identification, not Hy-MT2 translation acceptance.

Run `scripts/build.sh` with CMake3.25+ available through `CMAKE_BIN` or the local build/tooling runtime. It builds both fixed engines, provisions/hash-checks the language model in the developer build cache, and embeds the language runtime and attribution before ad-hoc signing the app. Direct Xcode builds require those prepared assets and fail if missing or invalid. Packaged candidates also include the translation worker and its license; its host is connected to NativeLyricsService. Both source checkouts must be clean at their exact commits. The Metal registry is `MTL`; an actual capability probe returned true. This is not proof of GPU model inference.

## Internet implementation and evidence — 2026-10-20

- `ShareCrypto` uses CryptoKit AES256-GCM and HKDF-SHA256. Salt is fixed .NET GUID byte order; JSON UUIDs are lowercase because the frozen receiver compares textual IDs and constructs case-sensitive object names. Manifest wire is nonce12/cipher/tag16; file wire cipher/tag16; chunks5MiB. Master key lives in memory and the returned fragment, never in the custody database, request headers, diagnostics or Keychain revoke record. Swift copy-on-write memory means no claim of exhaustive byte zeroization.
- `InternetShareStaging` copies bounded reads into a0700 per-share lease with0600 payloads, checks source hash/size/change metadata and fsyncs before remote creation. Descriptor-relative no-follow IO, known numbered files and an owner marker constrain cleanup. Unknown children/replaced/hard-linked files refuse cleanup. A marker-only partial initialization or empty reserved directory can be reclaimed. No recursive deletion of original sources.
- `InternetShareStore` reserves one of128 durable custody slots before staging/creation. SQLite records state/expiry/cleanup obligations; Keychain holds the authenticated backend session. All mutations share one gate across Keychain suspension. Remote and local cleanup errors are independent. Persisted Keychain-account deletion outbox survives a deletion failure. A creation request whose reply/capability is lost remains pending until expiry; it is never reported as confirmed revoked.
- `InternetShareService` uses shared transfer/connection/bandwidth budgets. Transfer admission has30min deadline; HTTPS create/upload timeout30min, explicit revoke2min, failure cleanup15s independent of caller cancellation, startup incomplete cleanup3s total. Completed shares survive restart. Local staging is retried independently. Shutdown retains task ownership and reports unconfirmed retirement after10s instead of declaring successful drain; blocked filesystem/Keychain retirement still requires explicit validation.
- Production Web PKI trusts system anchors/hostname only; device pinning exceptions are not reused. HTTPS response size64KiB and object/manifest limits are checked, redirects refused. Upload sends64KiB bandwidth-accounted pieces. Native management has Copy/QR/confirmation/retry and entry points in Settings/workspace/context menu. URLs are retained only for the current process, with an explicit explanation after restart; persisted revoke capability remains usable without retaining the master key. New creation toggle never revokes existing links. The native setup panel is actionable even when no backend is configured, explaining unavailability rather than inventing a successful share.

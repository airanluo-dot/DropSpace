The expanded suite preserves the original30-call control and the exact prompt/sampler. It runs original48-line lyrics in both targets, then a new12-line multilingual holdout frozen before execution (hash in expansion-protocol.json), and one cancellation after the first non-whitespace native output while the child is still alive. Fresh semantic-check notes are not part of the model-facing types or prompt. This is still QA and does not establish App incremental display or automatic language detection.

The existing App backend boundary can accommodate host-mapped plain-text results, but its current GGUF coordinator builds JSON batches and the runner applies a JSON schema. A production plain-text path would need an explicit separately versioned backend/protocol and cache identity, native tokenizer budget checks, complete-line validation and atomic complete-song cache writes. The current whole-document async result does not provide incremental UI updates. At roughly3seconds per line, progressive display would be useful, with generation/track identity checks to discard stale updates and incomplete results kept out of the full-song cache. These are integration recommendations, not implemented changes or quality approval.

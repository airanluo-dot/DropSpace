# DropSpace v0.3.0-preview.22 Native Island test plan

This plan maps the Preview.22 Native Island integration to automated and hosted acceptance evidence. It does not infer physical Windows behavior from a Linux workspace or from static source inspection.

## Automated acceptance mapping

| Area | Acceptance gate | Evidence |
| --- | --- | --- |
| Activity routing | Drop wins over manual expansion, notifications win over media, source updates replace in place, and expired activities disappear | `Preview22NativeIslandTests` and router source review |
| Media session | SMTC metadata/artwork/timeline/control projection is bounded; unavailable SMTC does not block startup | Windows Release build, app policy tests, and runtime smoke |
| Lyrics | LRC multi-timestamp parsing, normalized lookup, delay bounds, provider/local cancellation, and no startup wait | Core parser tests, locked restore, Windows smoke |
| Spectrum | Samples are active only while the media session is playing; process-loopback capability is preferred and endpoint meter fallback is explicit | Windows CI/API projection and target runtime evidence |
| Notifications and volume | Notification access is opt-in; volume changes are observed without flyout replacement or keyboard hooks | Windows CI/source gate and target runtime evidence |
| Widgets | Clock/calendar/resource/settings model uses normalized 6×3 placement and compact projection | `Preview22NativeIslandTests` and settings validation |
| Settings | Schema 12 migrates older settings with new defaults; nested changes merge and rollback through the existing coordinator | Infrastructure settings migration tests and App CI |
| Localization | en-US and zh-CN resource names and placeholders remain identical | `Test-Localization.ps1` |
| Compatibility | Every current package/project/manifest/installer/update path uses minimum build 20348 | `Test-WindowsCompatibility.ps1` and update-manifest tests |
| Packaging | Release version, five public assets, checksums, updater metadata, and website/API publication agree | Windows Release, website deploy, and live verification workflows |

## Required hosted suites

- Core, Infrastructure, and App tests with locked restore.
- Release-version/consistency, localization, compatibility, hardcoding, secret-hygiene, and brand-asset gates.
- WinUI Release build, x64 portable EXE, unsigned MSIX, identity package, Inno installer, installer lifecycle, and en-US/zh-CN portable smoke.
- Post-publication GitHub Release asset/hash checks and official website release API synchronization.

## Physical evidence boundary

Record results on Windows build 20348 and Windows 11 for media players using SMTC, online and local LRC, notification permission denied/allowed, volume changes, process-loopback availability/fallback, 100–200% DPI, one/two/three monitors, sleep/resume, and long-run timers. Until those rows are recorded, they remain `CONDITIONAL`.

## Release gate

The final release tag is `v0.3.0-preview.22`. Preview.21's tag, release, assets, and history must remain untouched.

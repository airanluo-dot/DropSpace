# DropSpace v0.3.0-preview.19 architecture-remediation test plan

This plan is the executable acceptance record for the Preview.18 architecture
remediation. Hosted Windows CI/release proves the build and automated rows;
real Windows, two-device, deployed Worker, browser, DPI, OLE, accessibility,
and performance rows remain explicit evidence requirements.

## Automated acceptance mapping

| Finding | Acceptance gate | Evidence |
| --- | --- | --- |
| F-001 | Batch pin and undo use one database write gate and transaction; missing/pending/duplicate IDs are reported as actual rows | Infrastructure repository tests |
| F-002 | Clipboard admission stops first; worker cancellation is awaited or managed resources remain owned after timeout | App lifecycle tests / Windows CI |
| F-003 | DropLink shutdown retains finalizer, gates, CTS, and staging until terminal retirement | Infrastructure lifecycle tests / Windows CI |
| F-004 | Nearby disposal is idempotent and retains server ownership through a late stop | Windows CI / lifecycle tests |
| F-005 | Expired shares are pruned before creation; live shares are never evicted at the hard cap | Nearby tests |
| F-006 | Segmented deferred-delete journal retains every owned obligation across restart, malformed input, and partial drain | Payload-store tests |
| F-007 | Revoke handles prune expired entries and reject at capacity before backend creation | Revoke-store tests |
| F-008 | PairingPending → Trusted and UnpairPending transitions are durable; authentication requires Trusted plus a usable secret | Transfer repository/pairing tests |
| F-009 | Secure share bytes are staged once, hash-checked, then uploaded only from the immutable app-owned stage | Share upload tests |
| F-010 | UNC/network metadata uses bounded concurrency, a timeout, and a short cache without releasing a gate early | File-reference tests / Windows CI |
| F-011 | Canonical release publication is owner-only, main-only, and rejects an existing tag/release | Workflow inspection and release run |
| F-012 | Pin mutation is a transaction-owned use case, not a ViewModel per-row loop | App source review / App tests |
| F-013 | NuGet lock files are required and CI/release restore in locked mode | Locked restore |
| F-014 | Main/tag protection is checked as a repository-admin platform boundary | GitHub settings evidence |
| F-015 | Release publication is create-once and fails on an existing version identity | Release preflight / GitHub Release |
| F-016 | Release uses `windows-2025` and records tool/image metadata | Build-environment artifact |
| F-017 | Update recovery parses all cache entries before selecting the highest valid version | Update-state tests |
| F-018 | Compatibility matrix records PASS/FAIL/CONDITIONAL honestly; hosted Windows is not physical evidence | `compatibility-baseline.md` and this file |
| F-019 | DNS-SD browse cancellation owns and observes ReceiveAsync before socket disposal | DNS-SD tests |
| F-020 | Identity serialization, DPAPI buffers, and certificate PFX buffers are zeroed after use | Source review / Windows tests |
| F-021 | Credential/environment suffixes are ignored, the tracked-tree hygiene gate is green, and repository secret scanning/push protection is the platform control | `.gitignore`, `Test-SecretHygiene.ps1`, GitHub settings |
| F-022 | Public and build declarations are x64-only until ARM64 has separate evidence | Compatibility script |
| F-023 | MainPage subscriptions attach on Loaded and detach on Unloaded exactly once per load | App source review |
| F-024 | Legacy overlay fields have a one-time migration and retirement window, with schema/version tests | Settings tests and decision record |
| F-025 | Bounded log drops expose a counter and emit an emergency power-of-two diagnostic plus final summary | Logger tests / diagnostics |

## Release gate

The release tag is `v0.3.0-preview.19`. Required outputs are the five public
assets (`DropSpace-x64.msix`, `DropSpace.exe`, `DropSpaceSetup.exe`,
`SHA256SUMS.txt`, and `update-manifest.json`), a matching GitHub Release and
release notes, the website release API, `latest-change.json`, and live website
verification. Stable signing rules and all local-first/source-safety,
redaction, FTS/keyset, updater, and Win10 Build 17763 invariants remain in
force.

## Physical evidence boundary

Until recorded by an actual target, OS/DPI/monitor/provider/OLE/accessibility,
two-device LAN, deployed Worker/browser, performance, and installer-manual
rows are `CONDITIONAL` rather than passing by inference from hosted CI.

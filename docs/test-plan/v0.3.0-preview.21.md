# DropSpace v0.3.0-preview.21 settings and action usability test plan

This plan records the acceptance evidence for the Preview.21 settings reliability and Quick Action usability changes. Hosted checks establish build and contract evidence; they do not replace physical Windows, accessibility, multi-device, browser, or long-run validation.

## Automated acceptance mapping

| Area | Acceptance gate | Evidence |
| --- | --- | --- |
| Settings merge | A stale form changes only fields it edited and preserves the latest pause/update-check values | Core policy tests and settings coordinator checks |
| Settings isolation | A local preference does not restart startup registration or initialize a failed optional network service | Settings coordinator regression checks |
| Settings recovery | Forward failures report a stage and correlation ID; rollback is reverse-order and retries only failed compensation steps | App coordinator tests/source review and Windows CI |
| UI thread safety | Successful and failed settings updates assign visible state through the dispatcher; overlay notifications are differential | App tests/source review and WinUI CI |
| Quick Action projection | Image Automatic profile prioritizes resize, conversion, and metadata removal; More is the remaining registry projection | Core Quick Action policy tests |
| Hash result | SHA-256 text equals the exported checksum, repeated exports never overwrite, and the source remains unchanged | Infrastructure hash action test |
| Image presets | Original/75%/50%/25% preserve aspect ratio, custom dimensions stay bounded, tiny images remain at least 1×1, and oversized sources are rejected | Core image preset tests and WinUI image tests |
| Localization | New labels, setup guidance, stage names, and result controls have synchronized en-US/zh-CN keys and valid placeholders | Localization gate |
| Packaging | Release version, notes, checksums, manifest, installer, portable EXE, and MSIX agree | Windows Release workflow |

## Required regression suites

- Core, Infrastructure, and App tests
- Locked restore, release-version/consistency, hardcoding, compatibility, and secret-hygiene checks
- Portable en-US and zh-CN resource smoke
- WinUI Release, portable, MSIX, identity, installer, and disposable installer lifecycle validation
- Quick Action output/source-safety, settings rollback, startup registration, and optional device-service retry checks

## Hosted evidence

The publication candidate is accepted only when the commit-linked Windows CI, Release, website deployment, and secret-scan workflows are green. The final report must record the exact commit, test totals, artifact names/hashes, GitHub Release URL, website deployment run, and live release API result.

## Physical evidence boundary

Until directly recorded on actual targets, Windows 10 1809/22H2, Windows 11, mixed-DPI and multi-monitor, Explorer/SMB/OneDrive/virtual providers, OLE/cursor/accessibility, startup registration, two-device LAN handoff and clipboard, deployed Worker/browser, disk/permission failures, and long-run performance remain `CONDITIONAL`.

## Release gate

The final release tag is `v0.3.0-preview.21`. It requires the five public assets (`DropSpace-x64.msix`, `DropSpace.exe`, `DropSpaceSetup.exe`, `SHA256SUMS.txt`, and `update-manifest.json`), matching version/hash/size metadata, successful GitHub Release publication, website release API synchronization, and post-release public download verification. Preview.20's tag, release, assets, and history must remain untouched.

# v0.3.0-preview.7 validation plan

Preview.7 is the completion-hardening release for the bounded 3.0 feature slice. Automated checks are the merge/release gate for deterministic policies and build artifacts; real Windows evidence remains required wherever the platform, network, or an operator-controlled service is part of the acceptance claim.

## Automated contract gates

- Core: UTF-8-bounded text/URL handoff, CRLF/URL normalization, SHA-256 integrity, label/sender validation, and `clipboard-paused` semantics.
- DNS-SD: mDNS query constants, `224.0.0.251:5353`, unsolicited announcement `QDCOUNT=0`/`ANCOUNT=4`, PTR/SRV/TXT/A parsing, private IPv4 filtering, stable-device deduplication, unknown TXT tolerance, malformed/truncated fail-closed behavior, and invalid key/fingerprint/port rejection.
- DropLink: deterministic canonical SAS ordering, complete bilateral state values, strict hello key/nonce/fingerprint validation, certificate pinning, authenticated request nonce replay protection, explicit handoff route, 1 MiB text/32 KiB URL limits, and receiver/session freshness.
- Clipboard: event-driven local capture, persisted Pause, no post-pause repository commit, no remote automatic import or system clipboard mutation while paused, and existing loop/self-write guards.
- Preview: bounded provider probes, native PDF page load/raster/page navigation/cancellation/cache-after-success, corrupt fallback, non-autoplay media controls/disposal, and image/text fallback behavior.
- Actions/sharing: capability-driven action IDs/providers, primary/More partition, source-safe image outputs, Nearby byte/range/header/expiry/revoke/no-listing checks, client encryption round trips, exact manifest/chunk wire order, deterministic HKDF/AES-GCM/Guid vectors, and revoke URL origin/share-ID constraints.
- Release: localization parity, CJK source policy, version/notes/README/ROADMAP consistency, Worker syntax/static checks, Windows app build, portable/installer/MSIX packages, smoke, checksums, update manifest, and website/API publication verification.

## Required two-device Windows 11 matrix

Run on two physical Windows 11 build 26100+ devices on the same private network. Record OS build, display language, DropSpace version, network profile, firewall state, device IDs (redacted), and pass/fail evidence.

1. Enable Device Handoff on both devices; confirm standard mDNS discovery and duplicate suppression. If discovery or inbound capability is unavailable, verify the UI exposes manual endpoint/firewall-degraded guidance without broad silent rule creation.
2. Start pairing from each direction. Compare sender and receiver SAS values, confirm on both screens, and verify only then that both peer secrets and trusted-peer rows exist. Repeat reject, cancel, expiry, transcript mismatch, disconnect, and UI-close cases; assert no secret/trust row is created for each negative case.
3. Transfer a file, folder tree, multi-file set, text, and URL. Verify explicit receiver approval, staging containment, whole-file hash, no source mutation, reconnect/resume, cancel/reject, malformed chunk rejection, and no protocol-log payload/path leakage.
4. Send text and URL through the explicit handoff route. Verify receiver preview shows sender/kind/length/content, Accept creates a Temporary Space item, Reject/cancel leaves Space and Clipboard History unchanged, no URL is opened automatically, and the Windows clipboard is unchanged.
5. Exercise cross-device Clipboard Off/Manual/automatic text+URL/automatic text+URL+image. Pause each receiver during validation, import, and automatic clipboard-write races; verify `clipboard-paused`, no durable remote row, no system clipboard mutation, and no echo loop after resume.
6. Create/revoke/expire a Nearby link, test two receivers and a third-cap rejection, no directory listing, HTML/header escaping, invalid/ranged/unsatisfiable reads, source-length mismatch, and private IPv4 binding.
7. For an operator-configured HTTPS Worker/R2 deployment, create an Internet Share, inspect that only opaque ciphertext is stored, open the receiver with the fragment key, decrypt/hash-verify multiple files in the browser, test expiry and authenticated DELETE revoke, and confirm a revoked link cannot fetch objects.

## Operational release boundary

Hosted GitHub Actions Windows runners prove build, unit/integration policy, packaging, smoke, and release metadata. They do not replace the two physical-device matrix, a real Windows display-language installation, or a configured Cloudflare/R2 account. When either external gate is unavailable, record the result as **CONDITIONAL** and keep the UI/release notes fail-closed; do not mark Internet Share live from Worker source presence alone.

## Evidence retention

Retain the clean workflow SHA, run IDs, test totals/TRX, package sizes and Authenticode status, SHA-256 manifest, smoke markers for `en-US` and `zh-CN`, release URL, website API URL, physical-device matrix, Worker deployment revision/config review, and final default-branch SHA. Never retain raw clipboard payloads, source paths, URL fragments, private keys, bearer tokens, or unredacted screenshots containing them.

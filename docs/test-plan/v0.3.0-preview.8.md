# DropSpace v0.3.0-preview.8 compatibility test plan

This Preview validates the Windows 10 compatibility boundary while preserving
the existing 3.0 feature slice. It is conditional until the required Windows
evidence is attached to the release record.

## Build and static gates

- Run `scripts/Test-WindowsCompatibility.ps1` before restore.
- Run core and infrastructure tests, including the Build 17763 updater policy
  boundary.
- Build the x64 WinUI application, self-contained Portable EXE, unsigned MSIX,
  and Inno Setup installer.
- Run both `en-US` and `zh-CN` resource-context smoke tests.
- Confirm the generated update manifest reports `minimumWindowsBuild: 17763`
  and still validates exact assets, sizes, hashes, channel, and tag.

## Feature acceptance

1. Launch normally and through `--startup`; verify startup remains hidden until
   redirected activation, the tray is available, and a second instance exits
   cleanly.
2. Run clipboard capture/pause/resume, text/image/file-reference, retention,
   search, and clear flows.
3. Run Explorer/Desktop file and folder drags through Smart Drag v2 and
   Classic mode, then direct Compact/Expanded drops and external drag-out.
4. Verify physical-pixel placement at every configured scale and topology,
   including primary/non-primary monitors, monitor reconnect, fullscreen
   suppression, Escape, and high-speed cancellation.
5. On Windows 10, verify the base visual and that no Mica/DWM failure blocks
   launch or overlay interaction. On Windows 11 22000+, verify the optional
   modern visual path and its graceful catch/fallback.
6. Verify PDF/media/image/text preview and action capability states; absent
   optional APIs must show unavailable behavior without crashing the core drop
   flow.
7. Verify packaged Share Target only with a trusted identity package. Unsigned
   Portable/Setup builds must report that identity is unavailable and retain
   native DropSpace intake.
8. Run Setup lifecycle, Portable smoke, unsigned MSIX inspection, and update
   integrity/publisher tests.

## Evidence and release decision

Attach logs/markers and a table containing OS build, scale, monitor count,
deployment mode, language context, and result. Do not infer Windows 10 1809,
historical Windows 11, mixed-DPI, Explorer provider, or multi-device evidence
from source inspection or a hosted Linux runner. Preview.8 may be published as
conditional while those external gates remain outstanding, but its release
notes must say so explicitly.

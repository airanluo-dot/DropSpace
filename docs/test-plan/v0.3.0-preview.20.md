# DropSpace v0.3.0-preview.20 architecture-remediation test plan

This plan is the executable acceptance record for the Preview.20 follow-up to
the Preview.19 whole-repository architecture audit. It is updated from actual
implementation and test evidence; hosted checks never substitute for physical
Windows, multi-device, deployed Worker/browser, accessibility, or long-run
evidence.

## Automated acceptance mapping

| Finding | Acceptance gate | Evidence |
| --- | --- | --- |
| F-001 | Destructive item removal records app-owned payload-delete obligations in the same SQLite transaction; the janitor drains them idempotently after restart | Infrastructure transaction/recovery tests |
| F-002 | Share, DropLink receive, and staged-import roots have atomic, confined crash-persistent leases and restart reconciliation | Infrastructure lease/recovery tests |
| F-003 | DropLink folder sending never descends through directory reparse points and revalidates sources before opening | Windows reparse integration test / source review |
| F-004 | Remote metadata gate acquisition has a service deadline; stuck synchronous work retains its slots and later callers fail boundedly without creating extra workers | Infrastructure saturation tests |
| F-005 | Unreferenced owned payloads and temporary payloads are reconciled with confinement and a grace period; external references are never touched | Infrastructure orphan-reconciliation tests |
| F-006 | DropLink source enumeration is worker-owned, cancellable, bounded, and does not block the UI dispatcher | App/Infrastructure async enumeration tests |
| F-007 | Remote availability cache removes stale keys and enforces a hard entry cap | Infrastructure cache-bound tests |
| F-008 | Direct clipboard destructive APIs are removed or routed through the same deletion owner and outbox path | App architecture/source tests |
| F-009 | Device handoff, sharing, workspace mutation, and projection responsibilities have explicit use-case boundaries without changing UI semantics | App architecture tests/source review |
| F-010 | Brand verification runs against the clean checkout before any tracked generated asset is written | CI/release workflow inspection and stale-asset failure test |
| F-011 | Website, validation, signing, and publication jobs request only the permissions they actually need | Workflow permission audit |
| F-012 | Secret hygiene retains filename checks and adds bounded content scanning with pinned tool/version and safe redaction | Secret-scanner fixture test / workflow inspection |
| F-013 | Trusted update signer validation requires a trusted chain and an approved SPKI/thumbprint identity with rollover support | Update signer tests |

## Required regression suites

- Core tests
- Infrastructure tests
- App tests
- Worker tests
- website/release-contract tests
- locked restore and release consistency/version tests
- portable en-US and zh-CN smoke tests
- WinUI Release, portable, MSIX, identity, installer, and disposable installer lifecycle validation
- payload outbox/restart recovery, staging lease recovery, reparse escape, remote saturation, stale brand detection, and workflow-permission checks

## Physical evidence boundary

Until directly recorded on actual targets, Windows 10 1809 Build 17763,
Windows 10 22H2, Windows 11, mixed-DPI/multi-monitor, hotplug/sleep/RDP,
Explorer/SMB/OneDrive/virtual providers, OLE/cursor/accessibility, two-device
LAN transfer/clipboard, deployed Worker/browser, real disk-full/permission/
SMB-stall, and long-run performance rows remain `CONDITIONAL`.

## Release gate

The final release tag is `v0.3.0-preview.20`. It requires the five public
assets (`DropSpace-x64.msix`, `DropSpace.exe`, `DropSpaceSetup.exe`,
`SHA256SUMS.txt`, and `update-manifest.json`), matching version/hash/size
metadata, successful GitHub Release publication, website release API
synchronization, and post-release public download verification. Preview.19's
tag, release, assets, and history must remain untouched.

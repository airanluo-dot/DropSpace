# A useful three-mode selector: current evidence and bounded route

> Superseded for production: the user authorized cancelling AI selection. The shipping selector and both UI choices have now been removed; see [production removal and retained translation](beta11-production-selector-removal.md). The following document preserves historical reasoning and checks, not current shipping behavior.

The common source pipeline and ownership fixes are usable independently. The evaluated generative selector profiles are not ready to claim that all three modes work reliably. The next route should address a narrow recording-confirmation task and an explicit host/model contract, rather than downloading successively larger models or relabeling the deterministic winner as AI selection. Both Hy translation models and their prompts remain separate and unchanged. The newly reported native crashes are an independent urgent investigation; no selector finding is evidence of their cause.

Readouts: [0.6B](beta11-qwen-selection-evidence-readout.md), [4B corrected](beta11-selection-engineering-progress.md), [4B deterministic](beta11-qwen4-deterministic-readout.md), [8B](beta11-qwen8-selection-readout.md). The synthetic fixtures do not estimate catalogue-wide accuracy. None proves that every possible training or protocol for that model must fail. The missing collaboration-credit fixture is a conservative metadata contract, not proof that a lead-only real catalogue entry is a different recording.

The 8B calls take 13.546–17.631 seconds cold, with prompt evaluation alone 8.400–11.911 seconds on a two-core/four-thread cloud CPU and peak RSS about 7.86GiB under these engine defaults. Corrected 4B calls also take seconds, not 500ms. Warm residency removes repeated preparation only; it cannot promise to remove prompt computation. GPU/device performance remains unmeasured. A short fixture's cost does not establish the cost of a complete provider snapshot.

The official template, trailing-newline transport and observed EOS are now understood. Three failures are formatting failures; a native grammar can address representation but cannot demonstrate alias recognition or unknown-identity abstention. The new host performer check blocks missing evidence; it does not retroactively turn a raw failed model answer into a correct model answer. These distinctions prevent a timer, grammar or guard from being called an AI accuracy fix.

## One shared source path, three genuine behaviors

| Mode | Native presentation | Model's actual task | Honest fallback |
|---|---|---|---|
| Rules, default | Immediate strictly validated original; full native three-second translation window and public source priorities | None | Native result is reported as rules |
| AI assisted | Same original and source window; same bounded snapshot, including weak aliases | Confirm an ambiguous identity or a lone unresolved identity only. Return confirmed IDs or abstain | Cold, busy, insufficient, rejected or late model retains native result, never an invented AI success |
| AI selection | Same immediate original and source window; same frozen snapshot | Compare all eligible recording identities and return confirmed IDs in the declared quality order, including a useful weak identity when justified | Same fallback. A model execution that merely copies the default without identity evidence is not proof this mode adds value |

AI assisted may legitimately skip an unambiguous trusted identity; AI selection must actually invoke a qualified model when eligible rather than silently behaving as rules. An inferred decision may agree with the native winner and still be real inference, but qualification must separately show useful positives and safe abstention in genuine ambiguity cases. Neither mode should invent performer evidence or override an explicit recording-version conflict. Missing performer information may become available through the existing normal media refresh; it is not a reason for extra provider requests or online identity lookups during this selector phase.

## Narrow, reviewable implementation route

1. **Keep identity evidence separate from collecting a document.** The host's known-performer check, version/candidate admission and native baseline protections are mandatory. Native fallback remains unchanged. Album artist, album, duration and being the sole candidate cannot independently establish the target performer. Known but unresolved cross-script names remain eligible for actual AI judgement. Avoid artist-name whitelists or rules tailored to the six user songs.
2. **Use one constrained, versioned output contract.** A selector profile should emit a complete ordered list of confirmed snapshot IDs, or an empty list, through a native grammar. The host rejects invented/duplicate IDs, partial/truncated output, invalid current ownership and order that violates the declared policy. It must not silently reorder an invalid list or extract an ID from prose and label that AI success. Grammar is transport enforcement; model identity decisions still need evidence.
3. **Keep public quality policy fixed.** Native target translation first, preferred then backup then fixed remaining source order, valid word timing only within the same source, with model judgement after those priorities. Ranking cannot allow a weak high-quality wrong recording to replace a strict original. Model output and host validation must use the same priorities. Ordered-list qualification needs real positive, abstention, order reversal and quality-conflict cases frozen before inference; the existing single-ID corpus alone does not cover it.
4. **Evaluate a task-specific compact selector rather than larger generic chat weights.** A recording-pair confirmation/scoring model with explicit abstention is a candidate design, not an implemented or qualified model. It should be trained/distilled and calibrated on independently grounded recording identities, performer aliases, complete/incomplete credits, explicit versions and hard negatives. Split evaluation by artist/recording family so memorized fixtures cannot pass. If optional offline entity evidence is used, give it to the model as cited input; entity normalization alone remains a rule, never AI judgement. Training resources/data rights and an actual deployment runtime must be established before claiming feasibility on user hardware. No new weights were downloaded for this proposal.
5. **Integrate only a demonstrated profile.** Keep selector and translator catalogues/consent/cache identities distinct, reusing files by verified hash. A new native profile must state its exact template, sampler/grammar, context/output bounds, verified model and worker bytes, memory allowance and real request deadline. Replace both existing 500ms selector caps together; do not alter Hy translation parameters. One resident owner remains: actual cleanup precedes role replacement, translation wins over preparation, per-profile GPU failures remain sticky until a real preference change. A constantly busy/unsupported lane should return native fallback, not repeatedly load a model each song.
6. **Measure cold, warm and switching separately.** Qualification needs actual positive semantic improvement, no unsupported identity acceptance under the whole profile, stable candidate reversal, source-priority conformity and deadline/cancel/maintenance publication safety. Existing deterministic host checks supply some safety evidence, not model ability or Windows GPU evidence. Keep tiny essential regression checks and a small frozen native observation, rather than broad repeated suites. If the profile cannot fit the separate background budget, disclose that hardware/profile boundary and retain the native result.

The last two steps require a real integrated native profile and deployment evidence. The current generic completion artifact has no static engine library for building a selector locally; an authorized Windows producer would be needed once a concrete profile qualifies. Diagnostic-only artifact retrieval must not be widened into production release approval. The reviewed-source release override remains unchanged.

## Explicit limits

Feasible now: immediate originals; the full native translation window; bounded weak-candidate collection without weak previews; public priority independent of callback order; trusted cache previews while collecting; identity/retirement/cache guards; distinct model roles; one owned worker lane and retained GPU fallback state. The relevant focused checks have passed.

Not demonstrated now: a reliable general AI selector in all three modes; ordered confirmed-ID ranking; compact task-specific model training; resident 8B latency or memory; GPU/actual-machine cancellation; correctness for unknown artists absent from both target and candidate evidence. Missing data cannot be repaired merely by requesting a more confident model output. Upstream throttling also remains outside the selector's control.

No release should describe the evaluated 0.6/4/8B profiles as a completed reliable AI selection feature. A genuine model profile that both selects useful ambiguous positives and abstains when evidence is absent is the remaining qualification gate. Current crash reports additionally require their own system-level diagnosis before any corrective release claim.

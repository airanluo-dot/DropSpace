# Beta4 glass refresh tiers and lossless region sampling

User scope: preserve the island content, layout, material optics and low latency;
selectively optimize GPU work and add Standard / High / Very high / Ultra settings.
This is a local review build, not an installer or public release.

## Implementation

- Standard remains the default and retains the existing 30 Hz UI consumption timer
  and the session's original capture interval. High targets 60 fps; Very high 120;
  Ultra uses the existing display identity / monitor refresh-rate cache. Display
  change notifications refresh that cache and update the glass cadence. The
  existing one-window-per-monitor topology handles monitor changes.
- Higher tiers receive frame notifications independently of the UI. Only one UI
  notification may be queued, and the pending frame is replaced rather than
  accumulated. Lower-than-native targets pace notifications using compositor
  timestamps, avoiding callback timing jitter. Native-rate capture uses zero
  minimum interval and forwards fresh frames without another phase gate.
- Optional IGraphicsCaptureSession5 pacing is queried through its documented
  Windows SDK ABI. Older systems without that interface retain the original
  capture path; minimum OS/framework targets are unchanged. Actual fresh-frame
  throughput still depends on Windows capture, source changes, and UI scheduling.
- The old full-monitor CopyResource is removed from production rendering. The
  displayed WGC lease is retained so resize, position and optics changes can sample
  the same full source correctly; only the original padded island region is copied
  into the shader input. Three pool buffers serve displayed / latest pending /
  producer roles, replacing two pool buffers plus a separate full-screen copy.
  This is buffer ownership, not a three-frame playback queue.
- The HLSL, blur passes, sampling padding, alpha, optics and island UI are unchanged.
  The existing duplicate-render guard remains. No CPU pixel readback, approximate
  change detector, resolution reduction or frame interpolation runs in production.
- The refresh setting is normalized, merged and persisted independently. All ten
  UI languages include five new strings. Acrylic collapses the entire glass group,
  including the new selector, retaining its saved value.

API reference: [MinUpdateInterval](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.graphicscapturesession.minupdateinterval?view=winrt-26100).
IID and vtable were verified against local Windows SDK 26100
`winrt/windows.graphics.capture.h` (IGraphicsCaptureSession5, slots 6/7).

## Measurement boundaries

Moving-background samples run for ten seconds with real music still enabled.
Capture age is the consumed WGC compositor timestamp age at read, not end-to-end
input/display latency or GPU execution time. Geometry animation can add material
renders beyond new-background consumption; use captureFps to count fresh updates.
Static backgrounds need not generate new frames. Short samples are not stability
or battery-life qualification, and rare stalls remain visible in the JSON data.

The optimization removes a full 2560x1600 BGRA texture copy per consumed frame on
this screen. It reduces GPU copy work, not the number of pixels Windows must
capture. The footprint sample does not prove a sustained CPU/memory reduction;
higher refresh tiers intentionally do more work than Standard. Multi-monitor
hotplug and live OS refresh-rate changes were source-reviewed, not exercised on
another physical display. The prior native heap-crash boundary remains unchanged.

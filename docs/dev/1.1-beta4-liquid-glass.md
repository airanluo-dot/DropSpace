Owner: primary agent; no delegated work. Scope: island background material and
six native settings only. No full test suite, AI inference or public promotion.

## Reference and implementation

The supplied `E:/Dev/reference/WinIsland` is source at commit
`7527d34f224810f6c9f778e013b4d49de19aa4b3`. The installed reference executable
at `C:/Users/Razer/AppData/Local/WinIsland/WinIsland.exe` has SHA-256
`e07b4783f78c0695b6cd92e6bdb2b2b39f2ca2cffbd0aa8faa35c5d1a2319f92`.
Both were inspected read-only. Its Rust/Skia implementation establishes the
capture, optical parameter and gradient behavior; it is GPL-3.0 code. DropSpace
uses independently written C#/Direct3D/HLSL, not imported reference code.

The existing GPU-support assembly now exposes a background-only surface. It
copies the current monitor frame on the GPU, crops to the original island shape
plus bounded filter padding, applies separable blur, a rounded refractive edge,
RGB dispersion, dark tint and optional vertical black gradient. Content remains
in the existing XAML tree above it. The swap-chain presenter remains Apache-2.0
with an updated modification notice; music keeps its original alpha mode.

Default values are exactly the latest user screenshot: LiquidGlass, 1, 400, 75,
0, true. Missing fields upgrade through the record defaults; normalization bounds
numeric input and merges independent settings edits. Existing theme and geometry
preferences are retained. No `OverlayWindow.xaml`, island view, layout resource,
lyrics/provider/model or database change is included.

Windows Graphics Capture is memory-only. Sampling stops and GPU/capture objects
are released on hide, unload, style change and close. The HWND is excluded while
sampling to prevent recursive feedback, so screenshots/recordings omit the live
island. Capture/driver failures retain the existing Acrylic/solid fallback.
High contrast, disabled transparency/effects and remote-session policy bypass it.
The two package manifests declare the
[borderless capture capability](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.graphicscapturesession.isborderrequired).

## Documentation conflicts

- `DESIGN_SYSTEM.md` described Desktop Acrylic as the island material. The
  verified Beta3 `OverlayMaterialController` agreed; the user's newer explicit
  requirement supersedes that default. Beta4 adds its material section and retains
  the old shape/theme/content rules and selectable Acrylic fallback.
- `ARCHITECTURE.md` said the main window had no backdrop, but its current
  implementation already uses independent Desktop Acrylic. The affected paragraph
  now describes the verified separation; no main-window material behavior changes.

## Boundaries

The reference is a visual/behavioral guide, not a claim of pixel-identical output
across GPUs. Multi-monitor hotplug/DPI changes, capture denial, GPU device loss,
HDR, remote sessions and system accessibility changes were reviewed in source but
not all exercised on this machine. Existing theme colors are preserved as requested;
users can select Acrylic or adjust tint/gradient for their background. The
pre-existing native heap crash `0xc0000374` remains outside this change and is not
claimed fixed by these bounded runs.

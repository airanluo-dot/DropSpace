# Round 14 — asset retirement and native drag lookup capacity

Status: **implemented and locally verified within the controlled boundary below**. Final
production integration, independent source/probe review, and root authorization preceded
execution. One new combined `drag-native` scenario ran once and passed (exit 0), with no
failed or repeated execution. Existing restore assets were reused for one necessary normal
source-linked probe build; its pre-existing `EnableNETAnalyzers=false` remains unchanged.

The probe executes actual `ItemAssetWorkLifetime`, `DragStorageItemService`, and
`NativeAsyncLifetime` sources against a small controlled Windows.Storage boundary. Eight
old file lookups occupy all native slots while a ninth queues. Canceling and disposing the
actual asset owners cancels all nine callers; the queued old request never starts native
work. Native Cancel requests are independently observed, and all eight slots remain owned
while Completed is pending. Fresh work waits until the old native operations complete,
then succeeds. Bounded acquisition and return of all eight actual semaphore permits confirms
retirement drained; old callers remain canceled. No fixed sleep or completion polling is used.

Executed command from the repository root:

```sh
/workspace/.tools/dotnet-deb/usr/share/dotnet/dotnet run --project scripts/media-lifecycle-probe/MediaLifecycleProbe.csproj --no-restore --no-launch-profile -- drag-native
```

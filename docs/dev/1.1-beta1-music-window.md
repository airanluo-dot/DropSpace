# Independent music window — local delivery

This extends the existing **1.1 Beta1** local candidate. It does not publish an app,
tag, release, download URL, website or update feed. The earlier four content workflows
and local Agent access remain included. The user's later system-volume requirement
supersedes the attachment's conditional volume fallback.

## Implementation

- `App/Services/Media/MusicWindowService.cs` owns one explicitly opened window;
  `App/Views/Music/MusicWindow.cs` shares the existing `MediaViewModel`, commands,
  artwork, timeline, lyrics and secondary-lyrics preference. Closing only ends
  presentation. The new Music-page button and optional global shortcut reuse it.
- Cover, metadata, transport and lyric visibility use a single retained visual tree
  and interruptible 480 ms transitions through actual XAML geometry and opacity.
  Exiting lyrics collapse only after opacity reaches zero. Button interactions and
  active-line emphasis use bounded composition transitions. Reduced motion removes
  those animations; pause slows the background;
  minimizing stops background presentation and releases only this window's capture
  ownership. No second media engine or player-specific production integration exists.
- Portrait mode has a large-cover page and a compact-header lyric page. After four
  seconds without interaction, lyric-page controls fade out and the lyric viewport
  expands; pointer/key input restores them. Keyboard focus and held drag pointers
  preserve the controls. The lyric and translation buttons share one evenly spaced
  row **below system volume in every layout**. Translation remains available in cover
  mode. The final symbols use pinned Microsoft Fluent 20-unit SVG paths and 44-DIP
  native hit targets, with their MIT license included in the bundle.
- Music minimum size is 360 × 600 DIP, adjusted to the work area. Small work areas
  retain a scrollable body. Lyrics follow shared state changes; manual scrolling
  schedules one return after scrolling ends. There is no separate media polling
  loop, playback clock, lyric provider or volume listener in this window.
- `App/Services/Volume/WindowsVolumeActivityService.cs` reuses its existing singleton
  endpoint observer through presentation leases and adds serialized native writes
  to the default Windows output endpoint. It does not create a second monitor.
  The slider controls **system master volume**; nonzero changes unmute. Device loss
  disables the control and errors remain visible. Opening the observer does not
  manufacture an island volume-change event.
- `DropSpace.MusicBackground/` is a rendering library based on the pinned Lyricify
  commit `cbef8a667c02a01707c78c7e76dc67d65cf161ed`. It retains the native D3D11
  mesh, shader and artwork texture crossfade, with Apache-2.0 and modification
  notices. Upstream global audio capture was removed. Only the existing fresh
  DropSpace process-loopback signal drives audio response; absent data leaves ambient
  movement. The library targets this repository's .NET 10 and Windows App SDK versions.
- `MainWindow.xaml.cs` applies a minimum **860 × 600 DIP**, adjusted to the current
  DPI and available work area, including attempted programmatic undersizing.
- Agent catalog additions expose five explicit `music.window_*` operations and
  three Windows `volume.*` operations through existing authorization. The catalog
  now has 136 entries; this number is not a count of independently executed features.

The window deliberately excludes the screenshot's system indicators, top grabber,
microphone, favorites, more menu, Dolby label, shuffle, repeat, output selector and
queue. Normal Windows window controls remain.

## Focused execution ledger

- Eight Core shortcut cases passed: optional legacy default, normalization,
  invalid/conflicting gestures, clearing and merged settings.
- The native rendering library compiled independently with no warnings or errors.
- First full publish failed on two unsupported two-argument `Thickness` constructors;
  the reported XAML converter errors were downstream of that C# failure. The
  constructors were corrected. Second full self-contained publish passed.
- `native-first/checks.json`: 23 passed assertions and three explicitly unverified
  observations. Real D3D presentation advanced from 2 to 22 frames and remained
  at 72 frames while minimized. Single-window reuse, shared synthetic presentation,
  centered hidden lyrics, translation persistence, invalid-timeline behavior,
  missing content, cross-track invalidation, ownership release, actual endpoint
  volume 50 → 49 → 50 and native hotkey conflict/rollback were exercised.
- Desktop input on that build opened the existing music window from the main Music
  page, invoked the music hotkey once without invoking retrieval, hid lyrics, and
  adjusted/restored the visible system-volume slider. It also exposed insufficient
  checked-toggle contrast; that issue was corrected before the third publish.
- Third publish passed. `native-final/checks.json` recorded 28 passed assertions and
  three unverified observations, including actual four-page island hit testing and
  the main window's 1075 × 750 pixel minimum at 125% DPI.
- Fourth publish passed. `native-portrait/portrait-check/receipt.json` recorded 16
  passed checks for actual animation intermediate rectangles/opacity, retained
  elements, rapid interruption, four-second idle, native minimum and minimize/restore.
  The user then supplied a screenshot showing landscape action-button overlap. That
  layout was outside those 16 checks; the check result did not prove visual completeness.
  The action row and symbols were subsequently replaced.
- Fifth publish passed with no reported compiler warnings or errors. The final EXE's
  `native-controls-final/portrait-check/receipt.json` again passed 16 checks after the
  changed geometry. Its separate `layout-check/receipt.json` passed three actual
  arrangements: 1040 × 700, 600 × 600 and 480 × 800 DIP. Both buttons have the same Y,
  centers at the control area's quarter points, at least 12 DIP separation and at
  least 4 DIP clearance below the actual volume row. No hotkey, endpoint-volume or
  unrelated content/Agent suite was repeated for this layout change.
- The first silent native SMTC probe failed a combined fixed-position assertion;
  that failed receipt remains at `native-final/session-probe/receipt.json`. The
  improved three-layer probe at `native-portrait/session-probe-2/receipt.json` passed
  actual pause/resume/seek and cleanup. The player reached 60 seconds in about
  2.8 ms; SMTC and the shared owner first published approximately 65.92 seconds
  after about 5.95 seconds. This run establishes delayed timeline publication,
  but the old receipt lacked enough samples to prove its exact failure cause.

Native window/D3D/endpoint checks use actual Windows APIs. The principal UI fixture
uses clearly identified synthetic artwork, metadata and original test lyric text;
it never claims that synthetic playback states prove a third-party player or PCM
capture. A separate bounded SMTC probe records its own outcome.

Final artifact and integrity receipts are recorded in the aggregate
[local delivery report](1.1-beta1-delivery.md). The final music-window pixel review
and new screenshots remain unverified: Computer Use continued returning its
physical-Escape stop condition even after the user explicitly reauthorized it and
the JavaScript kernel was reset. No further input was issued after each stop.
Long touch/inertial scrolling, third-party player behavior and nonzero process-loopback
capture were not exercised by the silent probe or synthetic fixture.

# Windows Beta 7 灵动岛液态玻璃实测

2026-11-12。在 `4da45c9e` 上建立 `codex/beta7-glass-stability`，单独编译 Windows x64 便携预览。基线、候选、诊断输出都在独立工作树。日常应用和同期审查分支各自运行。本文的数据属于这一台机器，不能直接外推到所有 Windows 显示配置。

## 实现与改动

灵动岛为 .NET 10 / WinUI 3 桌面 HWND。Windows Graphics Capture（WGC）捕获所属显示器，排除灵动岛自身和指针。自由线程帧池在回调中保留最新到达的帧，替换尚未取用的旧帧。UI 线程取得纹理，在 D3D11 GPU 上复制带留边的灵动岛区域，执行全分辨率横纵两遍模糊（各 25 次采样）、圆角折射、RGB 色散与着色，最后通过带预乘透明度的 Flip Sequential 交换链和 `SwapChainPanel` 交给 DWM 合成。歌词、控件与前景动画在独立的 XAML 层。

| 已查明的问题 | 修改和证据 |
| --- | --- |
| 标准档原由 UI 定时器轮询，动态桌面已有新帧却要等下一次轮询。 | 标准档改用捕获回调，依 WGC 时间戳选择最新帧；同一会话最多挂起一个 UI 取帧通知。支持可选捕获间隔的系统同步设置间隔。静止前被节流的最后一帧由一次性计时器补交。250 ms 的定时器只检查显示器归属。实测见下表。 |
| 已排除捕获的 HWND 在静止背景上移动，WGC 可以没有新帧。旧版移动 32 个物理像素后仍显示原位置的玻璃。 | 位置确实改变时，在下一次合成时用保留的原图按最终屏幕坐标重绘。对真实窗口连续移动两次、在原地重新确认、移回原点，冻结捕获时旧版提交增量为 0 / 0 / 0，新版为 1 / 0 / 1。更换显示器会重新获取来源。 |
| 创建渲染器时，UI 线程重复编译相同 HLSL。 | 有 Windows SDK FXC 时构建期编译三个着色器并内嵌；只有 NuGet 构建工具时，首次使用编译且仅缓存成功的字节码。每个会话仍独立持有、释放 GPU 设备资源。在本机，三个 DXBC 与旧运行时编译结果逐字节相同，合计 9,732 字节。 |
| 玻璃已可见时，被遮蔽且已断开来源的 Acrylic 蒙版仍随展开动画构建几何。 | 仅在 Acrylic 实际启用时更新蒙版，回退时直接应用最新几何。基线的一轮展开 → 紧凑 → 再展开，累计几何更新计数 2 → 33 → 59。候选同场景整个过程无需创建该蒙版。 |

代码审查还发现首帧可能早于面板取得有效尺寸。候选在面板排版完成时补绘已保留的帧。隐藏会取消移动订阅、释放帧池、保留帧和 GPU 资源；旧会话的排队回调及异步失败不能改变新会话。已实测隐藏、重开、Acrylic 来回切换。首帧与 XAML 排版的特定竞态没有在桌面上强制重现。

## 同机前后对照

Windows 11 家庭中文版 build 26300，单屏 2560 × 1600、240 Hz、125% DPI。系统枚举到 Radeon 880M 和 RTX 5080 Laptop；未单独追踪 DWM 与 WGC 各自所用的适配器。每个样本使用同一真实 WinUI 灵动岛和 DWM 驱动的移动条纹，预热 1 秒、采样 10 秒，窗口在前台。标准档以 560 × 340 DIP 展开，输出 700 × 425 像素。两版采用相同的模糊 2、折射 100%、展开宽度界面值 100%、色散 75、暗色遮罩 0 和墨染外观。

| 标准档，连续两次 | 基线 | 候选 |
| --- | ---: | ---: |
| 每秒实际取用的新背景帧 | 23.47 / 23.77 | 29.97 / 29.96 |
| WGC 回调到 UI 取用，P95 | 15.93 / 16.28 ms | 0.21 / 0.21 ms |
| WGC 源时间到 UI 取用，P95 | 15.86 / 15.93 ms | 1.93 / 2.80 ms |
| 已取用背景帧的源时间间隔，P95 | 54.20 / 54.20 ms | 33.36 / 33.36 ms |

WGC 源时间与 CPU 回调到达时间是不同观测点，分别统计的 P95 不能相加。每个版本在同一输入帧上比较区域采样与整屏 GPU 参考路径，展开状态的 1,190,000 个 RGBA 字节完全一致。此比对不含桌面背景在两次运行之间的变化。

原标准档收到约 58 个背景帧/秒，候选在本机按该档目标收到约 30 个/秒。交给玻璃实际取用的帧更多、更及时。高刷三档原先已由捕获回调驱动。下面是各档的实测，帧数均指每秒实际取用的新帧。

| 档位与像素尺寸 | 基线 | 候选 | 观察 |
| --- | ---: | ---: | --- |
| 60 Hz，700 × 425，首轮两次 | 59.86 / 60.03 | 56.24 / 56.13 | 候选两次 WGC 输入也仅约 56 fps，取帧等待 P95 不超过 0.20 ms。 |
| 60 Hz，同尺寸反序复测 | 59.71 / 59.75 | 59.54 / 59.63 | 两版帧间隔 P95 均为 16.68 ms。桌面和 GPU 与其他运行的程序共享。 |
| 120 Hz，紧凑 112 × 42 | 101.08 | 106.37 | 帧间隔 P95 均约 16.67 ms，源到读取 P95 为 4.74 → 7.03 ms。 |
| 原生 240 Hz，展开 875 × 531 | 233.09 | 228.23 | 帧间隔 P95 均约 4.17 ms，源到读取 P95 为 2.68 → 3.17 ms。 |

### 哪些帧到了显示端

用 Intel PresentMon 2.6.0 记录预览 PID 的 ETW。在同一次真实 Present 调用的 QPC 范围内，匹配玻璃交换链的地址与 WGC 源时间，剔除系统标记丢弃及缺少显示时间的行。四段均为 Composed Flip、同步间隔 1。每次取第二个 10 秒运动样本中的约 7 秒，按旧 A、新 A、新 B、旧 B 顺序运行以排查顺序效应。口径是从合成器标记背景帧，到系统报告该玻璃帧显示。[WGC 时间戳](https://learn.microsoft.com/en-us/uwp/api/windows.graphics.capture.direct3d11captureframe.systemrelativetime) · [PresentMon 指标](https://github.com/GameTechDev/PresentMon/blob/main/README-ConsoleApplication.md)

| 运行顺序 | 内部提交 / 匹配 ETW / 有效显示 | 源到显示 P50 | 源到显示 P95 | 显示间隔 P50 / P95 |
| --- | ---: | ---: | ---: | ---: |
| 旧 A | 158 / 105 / 102 | 20.91 ms | 33.44 ms | 45.91 / 141.71 ms |
| 新 A | 208 / 188 / 188 | 12.54 ms | 29.20 ms | 33.36 / 62.58 ms |
| 新 B | 207 / 188 / 188 | 12.51 ms | 12.63 ms | 33.36 / 66.71 ms |
| 旧 B | 161 / 135 / 135 | 20.89 ms | 33.32 ms | 45.82 / 91.76 ms |

616 个 ETW 事件均唯一匹配，旧 A 有 3 帧标记丢弃，得到 613 个有效显示样本。缺少对应 ETW 事件的内部提交没有计入，也不能据此认定丢帧。下游提交到显示 P95 在 A 组 20.50 → 22.95 ms，在 B 组 16.69 → 12.74 ms。另一次只采集显示间隔的独立短测也见到候选偶发 142 ms 间隔及两次标记丢弃。桌面长尾仍存在，改善主要来自更早取得背景帧。少数 WGC 源时间比 CPU 提交时间晚至约 1.45 ms，分析保留有符号原值。

着色器准备另以 Release DLL 独立测量。每种方式交替启动六个新进程，首次准备中位数从 39.79 ms 降至 1.01 ms，缺 FXC 的兼容构建为 40.60 ms。同进程反复创建时，旧版中位数 34.93 ms，候选读取已缓存字节码的 P95 小于 0.001 ms。以上只测了字节码准备；窗口创建、设备创建和 DWM 显示仍需时间。

## 复现与实机边界

在 Windows 进入本工作树，使用 PowerShell 7。诊断进程创建独立配置，结果目录须为新目录。两次运行保持背景、显示器、应用缩放及刷新档一致。脚本可用于兼容的旧版；移动判定及材质切换命令须使用本分支诊断构建。

```powershell
$exe = './src/DropSpace.App/bin/x64/Release/net10.0-windows10.0.20348.0/win-x64/DropSpace.exe'
./scripts/Measure-LiquidGlass.ps1 -Executable $exe -OutputDirectory .local/standard-repro -Tier Standard -Samples 2 -CheckMovement -CheckLifecycle
./scripts/Measure-LiquidGlass.ps1 -Executable $exe -OutputDirectory .local/compact-repro -Tier VeryHigh -Compact -Scale 0.85 -Samples 2
```

需要复现显示阶段时，在第二个 PowerShell 中运行下面的命令，选择刚启动的诊断 PID。先验证路径和命令行指向上面的独立输出目录，然后在移动条纹可见期间采样。原始 CSV 可覆盖整个运行；分析工具按探针时间范围和交换链筛选。要复测旧实现的逐帧数字，须将仅用于诊断的 `GlassRefreshMeasurement`、交换链地址和源时间采样同步到基线，保持其原始调度逻辑。未加探针的历史基线支持应用端计数。

```powershell
$out = (Resolve-Path .local/standard-repro).Path
$target = @(Get-CimInstance Win32_Process -Filter "Name = 'DropSpace.exe'" |
    Where-Object { $_.CommandLine -like "*--liquid-glass-check*" -and $_.CommandLine.Contains($out) })
if ($target.Count -ne 1) { throw '请在独立诊断进程运行时采样。' }
PresentMon.exe --process_id $target[0].ProcessId --session_name DropSpaceGlass --qpc_time --v1_metrics --no_track_input --timed 7 --terminate_after_timed --output_file "$out/frames.csv"
# 第二次运动结束且文件写完后运行
$probe = Get-ChildItem "$out/run/refresh-*.json" | Sort-Object Name | Select-Object -Last 1
py scripts/analyze-glass-display.py $probe.FullName "$out/frames.csv"
```

- **混合 DPI 与多屏。** 将静态高对比文字或格线放在两台屏幕上，在 100% / 150% 及不同刷新率间移动灵动岛，然后展开和收起。核对折射是否来自新位置，圆角与内容是否同步。显示运行中改变分辨率或接拔外屏，确认重新捕获。这里实际改变了岛的像素大小，只有一块物理屏。
- **极端运动与资源恢复。** 在岛后播放横向平移画面，多次拖动、展开、隐藏、再打开。用 PresentMon 对照丢帧、显示间隔和尾延迟。一次生命周期检查不能证明长时间无泄漏；长时间将隐藏和重开循环与 GPU 专用内存水平一起观察。
- **HDR、远程与系统回退。** 在 HDR 显示器检查亮部色彩与边缘；本次管线为现有 SDR BGRA8。分别验证高对比度、关闭透明效果、远程会话、失去捕获权限及显示设备重置，再恢复桌面并重开灵动岛。已核对对应选择和清理代码；本机没有覆盖这些真实环境。屏幕发光延迟或物理撕裂需要高速摄像或光电测量。

Beta 4 的 `docs/dev/1.1-beta4-glass-refresh-tiers.md` 和 `docs/dev/1.1-beta4-glass-refresh-investigation.md` 记录当时标准档的轮询实现及历史数据，本版本采用上文的到帧调度。

Additional integration fixes:

- Old main-window Light/Dark preferences previously controlled the island too. A missing new field must preserve that chosen appearance on upgrade, while fresh defaults remain Follow. `IslandAppearanceMigration` inspects raw field presence, maps the former preference once, and never overrides an explicit island field. Both settings load paths use it; the normal load saves the migrated record. The existing two selected configuration cases were updated rather than adding executions.
- Applied the Core review's narrow bounded ASCII search-index path. It avoids building/lowercasing the entire clipboard body for a 65,536-character index. Full ASCII eligibility still scans the input; pending whitespace preserves the exact substring-after-trim result. Unicode and nonpositive-limit behavior retain the original normalizer. This establishes an allocation/work bound, not measured speedup.
- An exact-version literal required check would leave other versions without the required name, or allow an inactive job to qualify. A single final `Build and test (x64)` check now verifies the real selected producer result. It records maintenance-only outcomes explicitly, requires isolated or legacy producer success as appropriate, and fails if scope classification fails. Repository protection was not changed.
- PR #108's documented four website static failures came from a helper expecting one classification output while production emits two. Corrected the existing helper to parse and verify both `maintenance_only` and `release_version`; no cases were removed or executed. Release-action and historical Beta17 route contracts were updated for the intentional shared isolated route.

All first-round production fixes received source/diff inspection. Workflow YAML and XAML/resource XML parsed; relevant JavaScript syntax checked. No functional test cases were executed.

A definite independent lifetime defect exists in Beta10: `MediaApplicationIconService` DataReader.LoadAsync, `ThumbnailService` SetSourceAsync, `ImageDecoderPreflight` BitmapDecoder.CreateAsync and `NeteaseSmtcVerifier` thumbnail DataReader.LoadAsync use direct `AsTask(token)` while disposing their input objects on cancellation. Pinned [CsWinRT 2.2.0 source](https://github.com/microsoft/CsWinRT/blob/8649ee3eeb2445ca2a36d80d878ef60b96a6c65d/src/cswinrt/strings/additions/Windows.Foundation/Windows.Foundation.cs#L312) sets the task canceled immediately and separately calls native Cancel, so the wait can finish before native Completed. Existing `WindowsMediaSessionService.AwaitNativeAsync`/`MediaArtworkService` instead retain resources until native completion and cancellation callback exit. Reuse that ownership contract through a suitable shared helper; preserve UI affinity and retain independent ownership if presentation must cancel quickly. This defect is a candidate for a separate fix, not a proved explanation of either crash. No affected media/thumbnail code has been changed in this handoff.

Read-only audits did not find explicit early release in SMTC owner retention, audio Stop/worker completion, activation dual-owner parameters, capture-buffer release, composition QI/AddRef transfer, OLE fixed structs or glow pixel bounds. Two-second automatic audio recovery, late activation callbacks and CsWinRT event attach/detach remain possible dump investigation points, without sufficient evidence to call them root causes.

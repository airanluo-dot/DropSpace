# Selection engineering after the first 4B diagnostic

The 4B failures were investigated at the invocation layer before changing identity instructions. A deterministic classification control is justified next; repeatedly rewriting the prompt against six expected answers is not.

## Verified invocation defect and bounded causality

At pinned llama.cpp `7fe450e19305b828c199d602c23a8337aaa1f03b`, [common/arg.cpp](https://github.com/ggml-org/llama.cpp/blob/7fe450e19305b828c199d602c23a8337aaa1f03b/common/arg.cpp#L1798) removes one trailing newline for `-f`. The Qwen4 assistant generation prefix needs that newline. Byte-preserving `-bf` fixes this call defect, and the new diagnostic records both stored and effective input SHA rather than claiming the stored file always equals inference input.

[Template control run 37273858674](https://github.com/airanluo-dot/DropSpace/actions/runs/37273858674) at `c1ca914a0d25f0b620976ebdeadb4bbaebec93e0` retains the same instruction, metadata, sampler and original native bytes. Both arms display special tokens. Missing-artist c0 acceptance and reversed-alias NONE persist under both transports. The former empty Ed Sheeran answer changes from immediate official `<|im_end|>` to complete c1 under binary transport. Thus template correction has real value, but does not resolve the other semantics.

The fixed runtime also reclassifies ordinary vocabulary token 128247 `</s>` as EOG even though official Qwen EOS is 151645/151643. All eighteen observed terminations in this run were official `<|im_end|>`; the extra EOG did **not** cause the reproduced empty answer. Original output-reader tasks completed, no output/time/resource budget fired, and no prefix/token salvage was used.

## Independent corpus and results

`identity-validation-v1.json` was committed before inference. It uses synthetic metadata, not claimed provider captures: English/Japanese titles, reordered complete artist lists, missing artist evidence on either side, same-title versions, an independent cross-script artist relation in both orders, and literal template-token text in a metadata field. Model input contains only query/candidate metadata and the unchanged identity instruction; expected decisions and admission scores remain annotations. Data `<` is escaped to prevent `parse_special=true` from turning quoted metadata into assistant-role tokens.

There are six causal-control calls and twelve held-out calls. The byte-preserving control fixes one of three prior failures. Held-out calls produce eight expected decisions of twelve: valid known identity and version rejection work; target-unknown single candidate, candidate-unknown artist and incomplete multi-credit are accepted against the predeclared abstention contract; the Michael Jackson / 迈克尔·杰克逊 relation succeeds in only one order. The incomplete-credit example is a conservative **contract** failure, not proof of an actual wrong Sunflower recording: a lead-only catalogue credit may legitimately describe the same collaboration, and the existing strict matcher intentionally allows whole-credit subsets. That nuance does not erase the two wholly unknown-artist acceptances or alias order dependence. Missing-artist scenarios have strict/collected 9/9, and alias pairs 0/4, so those failures are genuinely admitted situations.

All eighteen calls exit 0 with confirmed owned cleanup; no timeout, resource failure or nonofficial-EOG termination. Binary calls take about 9.07–11.90 seconds including fresh load; prompt evaluation is 7.38–10.14 seconds, peak RSS about 4.36GiB. These are different cloud-host observations from the previous run, not a controlled speed claim or resident/GPU guarantee. Inference remains background work after native lookup, not a delay imposed on original presentation.

Artifact 11329129806 (`ai-selection-long-diagnostic-37273858674-1`) is 113,563 bytes, ZIP SHA256 `7cbc02156482c63805f4af09c056d6f31a30008336deffdd3f968623b6c3d95c`. ## Independent production architecture fixes

* Both AI modes now retain the same bounded weak candidates. A lone unresolved identity also triggers assisted selection. Strict validation alone controls original previews and the native fallback, so collecting a candidate is not confirming it.
* One public priority compares native target translation, preferred/backup/fixed remaining source order, then usable word timing within that source. Callback arrival and match score no longer reorder sources. A fast low-priority result cannot start the short drain window while a higher-priority source is still pending under the shared budget.
* A single source cache provides a trusted early preview for AI modes while collection continues. Only the strict native result enters that source cache. New source-v3/source-v6 keys retire older lower-priority winners once; trusted preferred-provider originals and usable translations retain compatibility. Full candidate snapshots are not falsely reconstructed from one cached document.
* The independent selector prompt conveys source ranks and escapes literal template markers. Fresh and cached model decisions that downgrade the trusted native result under public priorities are rejected without a success-cache write or an AI-success label. This is currently a single-ID experimental protocol; ordered confirmed-ID decisions still need a qualified model/profile and direct evidence.
* `AiSelectionModelId` and a separate selector catalogue detach selection from the translation choice. Only the existing Hy experimental identities are available until a new selector qualifies. Two Hy translation choices and frozen prompts remain unchanged. Shared package hashes reuse the same model file. Normalization/reload/configuration/preparation/retirement all include the independent role.
* One resident runner continues to own the operation/global lane. Preparation of a different model first confirms old-process exit and cleanup; waiting or active translation wins. Same-model helpers without selector support are retained rather than repeatedly restarted. No second resident runner was added.

One new Core check, seven focused Infrastructure checks and one linked actual `AiLyricsService` check passed. They cover independent settings/retirement, two AI modes and cached previews, single weak identity, public-priority rejection on fresh and cached decisions, callback-order reversal, waiting for a slower higher remaining source, and process replacement without overlap or active-translation preemption. Existing whole suites were not run. Linux fixture process-switch checks are not actual Windows model/GPU checks; the App-linked check is not a full WinUI build.

## Remaining decision boundary

A zero-temperature control on the unchanged independent corpus is a supported next experiment because this is classification and the current model samples with temperature 0.7. It must change only sampling, retain binary input/special-token telemetry, and disclose any failures. It cannot establish that greedy decoding fixes missing evidence or candidate-position bias before results exist.

Any unsupported identity acceptance or persistent order dependence blocks enrollment. Correct abstention is useful but all-abstain is not a working selector. Zero errors in this small corpus would still need representative genuinely admitted identity/quality cases and production generation/ownership checks; no numerical pass percentage substitutes for trustworthy engineering. The current Hy helper and host still have two 500ms caps, and the ranked confirmed-ID native profile is not yet implemented. No Beta11 publication has occurred, and no upstream rate-limit or real-device guarantee is claimed.

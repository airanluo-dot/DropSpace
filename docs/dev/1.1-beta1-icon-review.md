# 1.1 Beta1 icon and island toolbar review

Scope: local-only changes on 2026-10-23. No publishing, tagging, upload or update-source changes.

## Source inventory

The review enumerated all 225 C# and XAML files returned by `rg --files src/DropSpace.App`
with generated `bin`/`obj` files excluded. All 11 XAML files parsed as XML. Sixteen files
contain icon construction, icon-related styling or icon references; one is the existing
`MusicVisualSmoke` diagnostic. This is a source inventory, not a claim that every dialog,
language, theme and DPI combination was visually exercised.

| Surface | Assessment and resulting change |
| --- | --- |
| `OverlayWindow.xaml` and island page routing | Removed the Files-only duplicate collapse button. Search and collapse share one 48 DIP toolbar row on all four pages; each button is 36 × 36 DIP, with an 8 DIP gap. Page content occupies a separate row, preventing content from covering these buttons. Retrieval hides the shared toolbar and keeps its own back action. |
| `ExpandedIslandMusicView`, `MediaExpandedView` | Shared native subtle button styling and tooltips. Preserve 48/56 × 44 playback targets and the larger play/pause glyph; previous/next use explicit 20 DIP glyphs. Only the island player loses its former duplicate top padding. |
| `ClipboardIslandView`, `QuickRetrievalView` | 16 DIP action glyphs, minimum 36 DIP button targets, preserved pin-toggle checked state and localized labels. Clipboard no longer needs a one-off right header margin to dodge floating buttons. Search back uses the same action style. |
| `WidgetsExpandedView` | Page padding follows the common toolbar. Timer action grows from 32 to 36 DIP. Widget identity glyphs use shared system font styling; full-tile settings/clipboard actions retain native tile buttons and their existing labels/tooltips. |
| Main collection/navigation and module navigation | Preserve native NavigationView and MenuFlyout icons, existing icon-plus-text quick actions and text item actions. Transfer button shares the action style while retaining its 40 DIP navigation width and activity badge. Item-type font now uses the system symbol resource instead of hard-coded Segoe Fluent Icons. |
| Reference window | Replace typographic plus/minus with native ZoomIn/ZoomOut glyphs and the shared 36 DIP style; existing localized accessible names also provide tooltips. |
| Download/settings/module/widget editor | Keep explanatory text actions. Download icons use the system symbol font resource. Widget editor identity glyphs share the 16 DIP action style. Module inventory's icon-plus-title and native module navigation were already consistent. |
| Standalone MusicWindow / MusicPage | Inspected icon construction and communicated the hard-coded font issue to the window owner; no MusicWindow code was edited in this workstream. Larger music transport controls remain intentionally distinct. |
| Standard title bars, NumberBox, ToggleSwitch and native dialogs | Kept platform-provided controls; no custom replacements or emoji icons were introduced. |

## Shared implementation

`Views/DesignTokens.xaml` adds `DropSpaceActionIconStyle`, `DropSpaceIconButtonStyle`, and
`DropSpaceIconToggleButtonStyle`. Buttons preserve native hover, pressed, disabled and keyboard
focus states. `Services/IconButtonAssist.cs` shares an existing localized accessible name as
the tooltip, follows name changes, and preserves explicitly supplied/bound tooltips. Icon glyph
scaling is independent of text scaling; ordinary text labels continue to honor Windows text size.
There are no new resource strings or localization review updates in this workstream.

`OverlayWindow.Diagnostics.cs` exposes `DiagnosticShowPage` and `ObserveIslandToolbar` for the
native verification owner. Observations include physical XAML bounds, accessible names,
visibility, center hit-test ancestry and active content top. This checks actual arranged UI;
the source layout alone is not reported as proof of successful hit testing.

## Checks performed by this workstream

- Source inventory: 225 files; 16 icon-related files reviewed in context.
- XML parsing: all 11 App XAML files passed after the changes.
- `git diff --check` on the changed tracked App paths: passed.
- No new unit tests or full-suite execution. These are reversible presentation changes.
- No independent App build or native runtime run: root owns the combined build and the native
  validation agent owns four-page/retrieval screenshots and hit-test observations. Their runtime
  ledger is the authority for those results.

Readback of that owner's third-publish `native-final/island-{widgets,music,files,clipboard}.json`
confirmed all four pages used the exact same arranged search/collapse rectangles: search at
(476, 24), collapse at (520, 24), each 36 × 36 in root coordinates. Both center hit tests reached
their intended button on every page; each had a localized accessible name. The active content
started at Y=65.6, below the button bottom at Y=60. This is evidence from the existing native run,
not four extra test executions by this workstream.

Remaining visual coverage boundary: this workstream did not run all ten languages, high contrast,
200% text size, or mixed-DPI screen moves. The new toolbar reduces page content height by 24–34 DIP
relative to the prior page-specific top padding, so the combined native review must include the
music lyric viewport and widget timer row, as well as the reported toolbar overlap.

# 1.1 Beta2 local candidate

Owner: primary agent. No delegated agents, CI dispatch, push, tag, Release, upload,
website or update-feed mutation were used for this work. Beta1 publication is the
baseline; the new request authorizes Beta2 development, not Beta2 publication.

## Implemented changes

- `MusicLyricRow` consumes the existing `LyricsHighlightFrame` and provider word
  indices. Native text-element geometry drives completed and partial white text
  layers, including wrapped CJK and boundary whitespace. There is no second lyric
  provider, playback timer or audio capture. Untimed lyrics keep line highlighting.
- The independent music background consumes the existing process-loopback spectrum
  through the island's audio-response mapping. Four artwork layers use distinct,
  bounded scale responses. Missing/stale audio decays; it does not manufacture beats.
- Visible lyric rows use native compositor blur and a viewport-relative alpha mask.
  The current row stays sharp; distance increases blur. Interaction restores clarity
  through a 320 ms transition. Default WinUI focus no longer prevents idle effects;
  deliberate keyboard navigation preserves accessible portrait controls.
- Search starts without an automatic selection. Clicking the same result again,
  the explicit clear-selection action, background tapping or Escape can deselect.
  Passive refresh preserves an explicit null selection. Image/text preview replaces
  the list, grows the existing island from 560 x 340 to 760 x 580 DIPs (fitted to the
  work area), and restores its previous size and selected object on Back.
- Dispatcher-owned music-window disposal now occurs in the UI shutdown phase,
  before asynchronous service-container disposal can resume on a worker thread.
- The existing Agent window-state snapshot adds observed audio response/pulse,
  highlighted-character position and idle state. These are on-demand fields, not
  another background observer. The new clear-selection label has all ten UI locales.

## Crash investigation: one confirmed fix, one unresolved incident

Windows Application Error recorded DropSpace 1.1.0.1 failing at **2026-10-26
17:06:13 Beijing time**, exception **0xc0000374**, `ntdll.dll` offset `0x118095`,
report `4038194a-e50a-4e34-b937-ac5cbebd8572`. The user reported passive background
listening, with no preceding action. Adjacent drag-probe log entries are not proof
that drag handling caused this failure.

There is no accessible matching dump in the user CrashDumps directory. The system
WER archive denies access, and the old `crash.marker` predates this incident.
Auditing audio activation/buffer ownership, volume callbacks, artwork replacement,
native renderer disposal and existing native-operation ownership did not establish
the corrupting call. The event locates heap-corruption detection, not its origin.
**The 17:06 crash is not reproduced or proven fixed.** A matching native dump or a
repeatable reproduction is still required; a successful build or short playback run
does not close this issue. No global dump/monitor service or Windows setting was added.

Separately, the logs contain `Music presentation belongs to its UI dispatcher`
during asynchronous shutdown. It also reproduced when exiting the installed Beta1
at 17:52. The UI-phase disposal change addresses this demonstrated managed defect;
it must not be described as the cause or cure of the background native heap crash.

## Coverage limits

- Physical Chinese IME candidate navigation and external-application OLE dropping
  were not verified. The native fixture checks Chinese query results and retained
  file drag data; these are narrower claims.
- Physical multi-monitor/DPI combinations, all languages, all third-party players,
  prolonged playback and rare native memory corruption are not comprehensively tested.
- Four requested behavior areas have implementation and focused evidence. The
  native-crash request remains incomplete; this candidate is not a claim that all
  five requested fixes are finished or release-ready.

# Selector execution contract and remaining product decision

The reliable change completed here is an explicit qualification boundary, not a completed general AI selector. No evaluated Hy or Qwen deployment profile qualifies for production recording confirmation. Two existing Hy translation models and their translation prompts remain available and unchanged. No new weights, provider traffic, paid API or identity lookup was used for this change.

## Implemented behavior

- `AiLyricsSelectionModelCatalog.Qualified` is deliberately empty. Package discovery/removal and persisted selector IDs remain compatible; a package hash or native protocol handshake is insufficient to qualify recording identity. Enrolling a future profile must bind and review the complete model, native worker, template, output contract, sampler, resource limits and qualification evidence.
- `ILyricsSelectionRuntime.IsSelectionProfileQualified` defaults to false. The production `PlainHyLyricsBackend` checks the shipping qualification catalogue before readiness, preparation or inference. Test backends that exercise successful host contracts explicitly declare their simulated qualification; that is not evidence of actual model ability.
- `AiLyricsService` returns `Unqualified` with the exact native document before model verification/preparation/inference. Unsupported selector settings do not activate or change the translation resident's configured selection identity. Repeated identical preparation requests do not repeatedly queue work.
- The production media caller asks `SourceSelectionSettings` for effective collection settings. An unavailable selector uses the existing strict native search/cache path, avoiding weak-candidate collection and extra supplemental requests whose only purpose would be unusable AI selection. The user's saved three-mode preference is retained. This does not shorten native translation search or prevent supplemental sources needed for a real translation.
- Both language settings descriptions explicitly say that AI modes are not ready and currently use rules. AI translation remains independently available. No privacy text changes.
- The selector and resident pipe request now derive their deadline from the same twelve-second background ceiling. The host uses the smaller **remaining frozen-snapshot budget** and links it into the worker. The native provider window remains three seconds after the first trusted original; originals are already presented before this separate background phase. A snapshot is not given a new twelve seconds on retry, and the change does not qualify a model or promise twelve-second performance. The old independent 500ms timers are removed together.

## What remains necessary to deliver genuine AI modes

The original three-mode intent is not fully implemented by this qualification boundary. Both AI choices currently fall back to the real native rules path, and the interface discloses that fact. Publishing them as usable AI features would be inaccurate.

The concrete next project is a **recording verifier with explicit abstention**, followed by its native integration. It requires grounded, reusable identity data and a deployable model; neither is supplied by the fifteen synthetic 8B calls. Increasing generic chat model size, emitting parseable JSON or keeping all positive answers out cannot replace that work.

| Required adjustment | Concrete execution and acceptance boundary | User-visible consequence |
| --- | --- | --- |
| Treat missing performer evidence as a supported abstention | Host rejects blank target/candidate performer; complete credits and explicit version conflicts remain independent admission constraints. Unknown names with present strings still require actual verified model semantics | Some recordings remain on their native original when identity cannot be established; album artist/duration alone cannot manufacture confirmation |
| Define the AI task over the bounded fetched snapshot | Assisted confirms unresolved identities; selection confirms all eligible identities in that snapshot and emits a complete ordered confirmed-ID list or an empty list. Freeze independently grounded positive/negative, recording-family, reversed-order and priority-conflict cases before running a new profile | AI selection cannot promise comparison against every catalogue entry or every source response beyond the existing permission/request bounds |
| Build or obtain a compact task-specific verifier | Establish lawful grounded data, actual training/distillation resources, independent artist/recording-family evaluation and calibrated abstention. Optional offline entity evidence is explicit input, never silently renamed AI inference | General unsupported cross-script aliases are not solved immediately. There is no justified completion-time estimate from the current diagnostic evidence |
| Integrate one complete native profile | Version its ordered-list protocol; constrain whole output without ID salvage; validate IDs, duplicates, ownership, performer evidence and the public translation/source/word priority. Pin model/worker bytes and measure resource admission | No automatic model download. Actual GPU/CPU capability and a qualified profile are required before enabling these modes |
| Keep enhancement asynchronous and bounded | Measure cold, resident and role-switch behavior under the shared twelve-second deadline. Verify that queued/active local translation has its declared scheduling priority and that selector teardown completes before replacement | A successful late enhancement may arrive after the immediate original. Busy, expired, insufficient or abstaining inference keeps the native result. Twelve seconds is a ceiling, not demonstrated latency |

An acceptable future profile must show useful ambiguous positive decisions as well as safe abstention. All-NONE is not success. A finite corpus cannot establish zero catalogue-wide errors, and the current tests cannot certify population accuracy. The frozen single-ID Qwen diagnostic is not ordered-list or production-snapshot qualification. The current native helper remains the old experimental single-ID protocol; it has not been silently relabelled as the proposed new verifier.

The actionable release choice is therefore to deliver independently established native/provider and AI-translation corrections with these modes explicitly pending, or to keep the three-mode feature milestone open until the grounded verifier and complete deployment profile exist. The parent task owns that product/release decision. No version, tag, approval binding or release was changed here.

# 最小测试与开发规则

适用于 Windows、macOS、官网、分享服务、可选模块，以及维护这些代码的 AI。

1. 普通改动默认运行 **0 项功能测试**。能从编译或代码审查确定结果时，到此为止。
2. 修复可复现的问题，优先选 **1 个**最贴近用户操作的场景。只在还有独立的已知风险时补测；同一构建、同一输入的成功结果只用一次。
3. [核心用例清单](../../TEST_PLAN.md)列出仓库维护的全部功能用例。更换规则时同步更新对应断言。新增用例须指出现有用例漏掉的真实故障，能合并时优先合并。
4. PR、普通构建和发布自动执行 **0 项功能测试**。需要验证某个场景时可本地按名运行；需要整个核心清单时显式手动运行。
5. 输入在进入系统或跨越信任边界时校验一次。内部代码复用已验证的值。重试只用于已知暂时性故障，并有明确的终止条件。增加兜底或特殊分支前，要能说明它处理的实际失败。
6. 涉及用户文件、访问权限、数据库升级、下载来源和安装包签名或哈希时，保留对应的保护。编译、资源完整性和发布包校验按交付物运行一次。报告分别写明实际运行的测试、构建结果和未验证的范围。

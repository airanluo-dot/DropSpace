# Beta11 source adapter implementation

## Stage 1: Kugou KRC and business failures, QQ diagnostic code

Implemented in the shared cloud branch `fix/beta10-chinese-lyrics-regression`.

Kugou now validates explicit status/error codes and required payload shapes for lyric search,
catalogue search, hash search and downloads. A declared rejection is terminal, carries its code,
and cannot be reclassified as a broken recording by `LyricsCandidateRequests`. A legitimate
empty candidates/lists array remains a miss; an opaque HTTP-200 wrapper is a failure.

Downloads prefer KRC at the existing allowed endpoint using the same ID and access key. KRC
provides line-relative word timings and optional positional translation arrays. Type-zero
romanization is not translation. Type-one translation arrays must cover every original row
exactly, with valid row shape; partial arrays are ignored, preserving valid original words.
Language remains conservatively inferred because this format does not supply the host's
explicit BCP-47 provenance. No text or timing is generated by AI.

Bounds: 256 KiB packed bytes, 1 MiB inflated bytes, at most 128x expansion with a 64 KiB small
file allowance, 10,000 rows, 2,048 words per row, 24-hour timestamp ceiling, JSON depth 8,
eight optional language entries, cancellation checks and a 500 ms processing deadline.
Inflation reads at most 4 KiB between checks. These are cooperative finite-work limits, not
an OS hard execution timer. The implementation does not copy GPL parser code.

Malformed/unsupported KRC can fall back to LRC for the same recording, charged against the
existing total of three download requests. HTTP failures, business rejection and cancellation
do not trigger this fallback. A server returning plain LRC for fmt=krc is parsed directly.
Kugou now reports originals progressively while looking for native target translation. Existing
LRC-only source cache entries are revision-invalidated once; the new capability is not hidden
by an old cache. QQ rejection exceptions now retain the actual numeric API code.

Verification: three new offline fixture checks passed. They cover relative word timing and
native translation in one download; invalid base64/oversized inflation with bounded LRC
fallback; and business/malformed-search rejection without subsequent probing. The first test
attempt had a fixture error (missing HttpResponseMessage.RequestMessage), corrected before
the passing run. No existing successful tests were rerun. A final Infrastructure build after
static review compiled with zero warnings/errors. No real lyric endpoint was requested.

Remaining: actual live KRC variants and Windows runtime behavior; AMLL bounded search and
response contracts/cache; general artist aliases replacing the one-artist mapping; final
source-specific reverse review; candidate contracts and the separately reviewed optional AI
selection protocol. Beta11 release remains owned by the parent task.
